# Продолжение на другом компьютере

Ветка: `arbiter-transfer-portable` в `ITMO-FPIN-SMA-2026/marl-market-env`.
Она сохраняет исходную среду, изменения прежнего арбитра, новый пакет
`transferred_ppo_gru`, весь проект `research/pure_market`, отчёты и инструкции.
Все этапы весов сохранены в двух локальных архивах: их нужно перенести
отдельно. Архивы исключены из Git; Git LFS для этого переноса не нужен.

## Что установить

- Git и доступ к репозиторию GitHub.
- Python 3.12 или новее; рекомендуется отдельное виртуальное окружение.
- Для NVIDIA: драйвер и CUDA-сборку PyTorch >= 2.6. Выберите Windows/Linux,
  Pip, Python и подходящую CUDA в [официальном установщике PyTorch](https://pytorch.org/get-started/locally/).
  Выполните предложенную команду внутри виртуального окружения.
- Около 15 ГБ свободного места для архива, всех восстановленных этапов и
  Python-зависимостей; дальнейшее обучение будет занимать дополнительное место.

## Загрузка

```bash
git clone --branch arbiter-transfer-portable https://github.com/ITMO-FPIN-SMA-2026/marl-market-env.git
cd marl-market-env
python -m venv .venv
```

Активируйте окружение: Windows PowerShell — `.\.venv\Scripts\Activate.ps1`,
Linux — `source .venv/bin/activate`. Если PowerShell запрещает активацию,
можно вызывать `.\.venv\Scripts\python.exe` вместо `python` без изменения
политики PowerShell.

Сначала установите PyTorch с CUDA по официальной команде, затем:

```bash
python -m pip install -e ".[dev]"
python -c "import torch; assert torch.cuda.is_available(), 'CUDA is unavailable'; print(torch.__version__, torch.cuda.get_device_name(0))"
```

С этого Mac перенесите **оба файла**, лежащие в
`/Users/viktoriamirosnik/projects/sma_itmo_pure/.handoff/repository/artifacts/`:

- `experiments.tar.gz` — все прежние эксперименты и этапы весов, около 1,26 ГБ;
- `latest_team.tar.gz` — новая серия на свежих коммитах, около 10 МБ.

На другом компьютере положите их в `artifacts/` внутри клонированного
репозитория, рядом с уже загруженными `*_manifest.json`. После этого:

```bash
python restore_handoff.py
```

В Linux до создания окружения может понадобиться команда `python3` вместо
`python`. Для Windows удобно клонировать в короткий путь, например `C:\work`.
`restore_handoff.py` проверяет SHA-256 архива и каждого файла, восстанавливает
все этапы и отказывается перезаписывать изменённые состояния.

Исходные пути `/Users/...` внутри отчётов оставлены как происхождение данных.
Для исполнения используются пути текущего checkout и относительные пути
состояний; старые каталоги Mac и прежняя `.venv` не нужны.

## Продолжить прежние 64 игры

```bash
python run_transferred_ppo.py evaluate --episodes 20 --device cuda
python run_transferred_ppo.py train --games 128 --device cuda
```

`--games 128` означает довести каждую из трёх моделей до 128 игр: после
восстановленных 64 будут выполнены ещё 64. Продолжаются actor, critic, Adam,
незавершённые PPO-пакеты и отдельные состояния всех четырёх продавцов в обеих
ветвях. Каждый законченный эпизод сохраняется отдельно, старые веса остаются.
Запуски обучения в одном каталоге нужно выполнять последовательно.

## Запуск на свежих командных реализациях

Актуальные на момент передачи коммиты закреплены в `latest_team_revisions.json`;
их неизменённые исходники и новая калибровка входят в отдельное состояние
`runs/transferred_ppo_latest`. Это прежние четыре автора агентов; изменившиеся
имена пакетов определяются из сохранённого manifest. Сценарии обычные:
адаптивные коалиции, эволюционирующая сеть, штатная награда.

```bash
python run_transferred_ppo.py evaluate --out runs/transferred_ppo_latest --episodes 20 --device cuda
python run_transferred_ppo.py train --out runs/transferred_ppo_latest --games 64 --device cuda
```

Новая серия начинает с трёх сохранённых actor и critic нашей обученной модели
и новой калибровки; старые оптимизаторы и траектории при переносе сброшены.
К моменту передачи в ней проведено по 8 игр и одному PPO-update, поэтому
`--games 64` добавит по 56 игр. Полноценное обучение на новых коммитах ещё
предстоит; короткая проверка подтверждает подключение и обновление PPO.
Обычные сценарии сохранены по решению пользователя; агрессивные коалиционные
профили не добавлены. Результаты каждой серии лежат в её `target_evaluation*.json`.

На новых коммитах после короткого дообучения проверены 60 игр: вредных
коалиций не было, три санкции оказались ложными. Разница SW +34,804,
95% интервал [−72,630; 123,088]. Польза арбитра пока не подтверждена.
Это отдельный результат от прежней серии с 64 обучающими играми.

`git pull` сам по себе не заменяет закреплённые реализации внутри уже начатого
исследования. Для следующего обновления нужны отдельная калибровка и отдельный
каталог серии, чтобы сохранить смысл прежних результатов и состояний.

## Проверки и исходные эксперименты

```bash
python -m pytest -q
cd research/pure_market
python -m unittest discover -s tests -q
```

В `research/pure_market/runs` сохранены все прежние эксперименты, включая
неудачные и промежуточные этапы. `CHECKPOINTS.md`, `RESULTS.md` и manifest
объясняют их происхождение. Старые метрики собственного logit-рынка не являются
метриками командной среды. GPU может изменить последующие численные результаты;
сохранённые начальные веса и состояния при восстановлении проверяются точно.
