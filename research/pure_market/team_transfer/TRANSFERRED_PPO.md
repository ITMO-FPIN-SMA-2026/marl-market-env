# PPO + GRU на командной среде

Пакет `src/transferred_ppo_gru` подключает перенесённый арбитр через штатный
`ArbiterAPI`. Используется настоящий `social_market_env` этого репозитория.
Код среды, прежних арбитров и четырёх командных агентов не меняется.

Командные реализации Аскарова, Твердохлеб, Родиной, Жмуренко и политика коалиций
извлечены из локальных Git-веток в `runs/transferred_ppo/team_sources`.
Их коммиты и SHA-256 закреплены в `sources.json`; сеть и `git checkout` не нужны.
Среда загружается из `src/social_market_env`, дополнительный путь нужен только
для реализации Жмуренко. Файлы среды в кэш не копируются.

## Запуск

Из корня `marl-market-env`, используя Python с установленным PyTorch:

```bash
../arbiter_v2/.venv/bin/python -B run_transferred_ppo.py evaluate --episodes 20
../arbiter_v2/.venv/bin/python -B run_transferred_ppo.py train --games 64 --device mps
```

`--games 64` означает довести общее число обучающих игр каждой модели до 64.
Повторный запуск продолжает записанное состояние. Есть три независимых
перенесённых модели; каждая начинает с своего actor и critic из нашего обучения.
При обучении четыре настоящих продавца тоже учатся на собственных наградах.
Контрольная ветвь без арбитра получает такой же объём обучения.

Оценивание замораживает и арбитра, и продавцов. Отдельно измеряются:
полный эффект после адаптации, работа с теми же продавцами без арбитра,
и ошибки на независимых продавцах без коалиций.
Новые отчёты получают новые имена, прежние не перезаписываются.
Для нового набора проверочных миров можно задать `--eval-seed`.

## Что перенесено

Actor и critic скопированы без изменения численных весов и архитектуры.
Старые Adam, траектории и калибровка не переносятся. Формат target-checkpoint —
схема 4: линейный общий спрос командной среды, её logit-доли и SW как
потребительский излишек. Нормировка публичных признаков берётся из её параметров.
Сначала выполнена новая публичная калибровка на независимых командных продавцах.
Дообучение использует штатную награду `social_market_env.core.scoring`.
`SW*`, себестоимости, граф и истинные коалиции на вход сети не передаются.

Рыночная модель отличается от нашего logit-рынка с отказом от покупки.
Результаты благосостояния и точности из нашего рынка не являются результатами
командной среды. Файлы `initial_evaluation.json` и `target_evaluation*.json`
содержат её фактические результаты; отсутствие вредных коалиций не проверяет
способность модели правильно штрафовать при их появлении.

## Проверенный результат

Завершены 64 обучающие игры на MPS для каждой из трёх моделей: по 8
обновлений PPO. Сохранены 195 состояний сети (начальные и после каждой игры)
и оба набора продавцов после каждой игры. 37 тестов прошли.

В 12 288 обучающих раундах с арбитром было лишь 5 раундов с вредными
коалициями. При вероятностном исследовании выполнены 179 штрафов, 178 ошибочны.
В 60 новых проверочных играх конечная политика `greedy` не штрафовала;
вредных коалиций там также не было. Разница среднего потребительского
излишка после адаптации: +49,377, 95% интервал [−92,079; 199,214].
С теми же продавцами отключение конечного арбитра не меняет результат.
Рост благосостояния и способность адресно штрафовать пока не подтверждены.
По решению пользователя остаются только обычные сценарии; агрессивные
коалиционные профили не добавлены.

## Все состояния

- `initial_model_N.pt` — точные перенесённые сети до target-обучения;
- `train/model_N/arbiter/weights/` — каждый законченный эпизод PPO, Adam
  и незавершённые пакеты траекторий;
- `train/model_N/game_*/` — обе версии продавцов после каждой игры,
  метрики и полные сжатые логи среды;
- `train/model_N/progress.json` — совместное состояние арбитра и продавцов;
- `train/model_N/arbiter/index.json` — индексы NN-checkpoint с SHA-256.

У коалиционной политики в этой версии нет обученных весов между играми:
её убеждения сбрасываются методом `reset`; исходный код и настройки сохранены.
Исходные выбранные веса и старые `ppo_arbiter/online.pt` не перезаписываются.

Для подключения к другому штатному запуску класс компонента:
`transferred_ppo_gru:TeamPPOGRU`. Его конструктор принимает `market`,
`checkpoint_path`, `device`, `evaluation` и необязательный `state_dir`.
`state_dir` сохраняет каждый обучающий эпизод; для независимых запусков нужны
разные каталоги. Данный launcher дополнительно загружает сохранённые состояния
всех четырёх командных агентов и сохраняет их между играми.
