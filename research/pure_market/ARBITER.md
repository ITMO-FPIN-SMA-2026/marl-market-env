# PPO + GRU

Основной арбитр — исходный PPO с отдельными actor/critic и GRU.
`market_rl/arbiter_v2/model.py` побайтово совпадает с моделью из
`sma_itmo/arbiter_v2`. Внешний репозиторий не меняется.
MLP сохранён как отдельный эксперимент: [история](MLP_EXPERIMENTS.md).

## Чередование обучения

```bash
python -m market_rl.arbiter_v2.alternating \
  --market runs/logit_prepared_market/agents.json \
  --out runs/ppo_learning_recipients --device mps \
  --learn-during-ppo --initial-fine-probability 0.5 --seed 130000000
```

Нужны зависимости из `requirements-arbiter.txt`. В текущем окружении PyTorch
доступен в `/Users/viktoriamirosnik/projects/sma_itmo/arbiter_v2/.venv/bin/python`.
`mps` использует GPU Mac, `cuda` — NVIDIA, `cpu` — процессор;
`auto` выбирает доступное устройство. Явно заданный недоступный GPU вызывает ошибку.

Цикл состоит из трёх этапов:

1. PPO собирает полные эпизоды, в которых продавцы и коалиции тоже обучаются.
   Параметры самого PPO фиксированы до конца пакета, после чего выполняется
   PPO-update. Контрольная ветвь получает такое же число обучающих эпизодов.
2. PPO фиксируется; четыре продавца, коалиции и одиночные эталоны обучаются
   под его санкциями. Контрольная ветвь без арбитра получает столько же
   эпизодов обучения из тех же начальных весов.
3. Обе ветви замораживаются для проверки на отдельных validation-сценариях.

По умолчанию: 8 циклов, 32 PPO-эпизода и 32 эпизода адаптации в цикле,
3 независимые инициализации PPO. Это 32 PPO-update на инициализацию.
Размеры сети, PPO/GAE, финансовая награда продавцов, награда арбитра,
штраф 25, бюджеты и режим исполнения `greedy` сохранены.
В согласованном новом прогоне исходная вероятность штрафа равна 50%.
Это только инициализация bias: дальнейшие вероятности определяются обучением.
Одиночные эталоны обучаются в отдельном этапе адаптации обеих ветвей.
Без `--learn-during-ppo` сохраняется предыдущий протокол с замороженными
продавцами во время PPO; он использован в `runs/ppo_alternating/`.
На исполнении доступны только публичные наблюдения; скрытые коалиции
участвуют исключительно в расчёте скалярной награды и внешней оценке.

## Выбор и проверка

По согласованию добавлен этап предварительного обучения исходного actor:

```bash
python -m market_rl.arbiter_v2.alternating \
  --market runs/logit_prepared_market/agents.json \
  --out runs/my_pretrained_ppo --device mps --learn-during-ppo \
  --initial-fine-probability 0.5 --seed 210000000 \
  --cycles 4 --pretrain-epochs 20
```

Для него собираются 400 обучающих и 80 отдельных проверочных эпизодов.
Входами actor остаются публичные последовательности. Метки правильных действий
вычисляет оценщик по истинным коалициям; в actor эти сведения не передаются.
Actor обучается на CPU, затем возвращается на выбранное устройство PPO.
Critic в этом этапе не меняется; PPO продолжает обучение с новым Adam.
Дополнительных сетей и выходных голов нет. Каждый supervised-epoch сохраняется
в `pretrain_epoch_NNN/`, включая его Adam и RNG; выбранный этап —
в `pretrain_selected/`. В `initial/` остаются случайные веса до любого обучения.

В запуске `runs/ppo_pretrained_actor/` использованы также две последние
финансовые популяции из предыдущего прогона. Их пути и SHA-256 перечислены
в `run_config.json`; `--pretrain-source` позволяет явно указать такие источники.
Сами исходные популяции при сборе данных заморожены.

Выбор checkpoint использует только validation: положительную разницу чистой SW,
точность санкций не ниже 90% и минимум 10 санкций на проверочных играх.
Если подходящего checkpoint нет, сохраняется явно неквалифицированный вариант.
Финальные test-сценарии открываются после выбора во всех независимых запусках.
В отчёте есть парный bootstrap по запускам и целым играм, точность санкций,
пропуски, банкротства и отдельный контроль без коалиций.
Положительная точечная оценка сама по себе не подтверждает пользу.

В `replica_N/selection.json` указан выбранный каталог с `arbiter.pt`,
`regulated.json` и соответствующей контрольной ветвью `baseline.json`.
Подключение выбранного PPO:

```bash
python -m market_rl.train --load PATH/regulated.json \
  --arbiter PATH/arbiter.pt --arbiter-device mps --evaluate --episodes 50
```

## Сохранение и продолжение

`replica_N/weights/initial/` содержит случайные веса перед обучением.
Сохраняется каждый PPO-update и каждые 16 эпизодов адаптации, включая конец
каждого этапа. Каждый snapshot содержит actor, critic, оба Adam, все рыночные
таблицы обеих ветвей, одиночные эталоны, RNG и положение в цикле.
`weights/index.json` содержит SHA-256 файлов. Старые этапы не перезаписываются.

Для продолжения прерванного запуска повторить ту же команду с `--resume`.
Параметры и исходный рынок должны совпадать. Продолжение проверено на CPU
до совпадения весов и результатов; GPU может иметь численные различия.
Короткая проверка с одной инициализацией не выдаётся за подтверждение пользы.
Checkpoint ранней адаптации со схемой 2 остаются в архиве и требуют её кода;
текущая схема 3 явно фиксирует тип спроса, нормировку SW и критерий вреда.
