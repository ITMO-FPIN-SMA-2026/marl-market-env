# Рыночная MARL-среда с коалициями

Минимальная реализация по `Сводка ЛР АСС осень 2026.docx`.
В рынке **четыре агента**, как запрошено, вместо 12+ из общей постановки.
Логистики нет. Базовому рынку нужны Python 3.10+ и NumPy.
Арбитр — PPO + GRU по публичным историям:
[обучение с адаптацией продавцов](ARBITER.md). Исходная архитектура восстановлена;
эксперименты MLP сохранены отдельно.
Его можно включать отдельно; базовый запуск остаётся без арбитра.
Проведённые обучения и их ограничения: [результаты](RESULTS.md).
Арбитр также подключён к настоящему `sma_itmo/marl-market-env`:
[запуск на четырёх командных агентах](team_transfer/TRANSFERRED_PPO.md).
Обычные сценарии сохранены; полезность санкций после переноса пока не подтверждена.
Исходный `Stochastic RL_bench (1).ipynb` сохранён: из него взято разделение
среды, индивидуальной политики, награды и обучения; логистические классы
и алгоритм обучения из ноутбука не переносятся.

## Запуск

Из корня проекта:

```bash
python3 -m pip install -r requirements.txt
python3 -m market_rl.train --episodes 300 --steps 100 --output runs/demo
python3 -m market_rl.train --load runs/demo/agents.json --evaluate --episodes 20
python3 -m unittest discover -s tests -v
```

Два отдельных режима спроса:

```bash
python3 -m market_rl.train --demand-model assignment --output runs/assignment
python3 -m market_rl.train --demand-model logit --episodes 1000 --output runs/logit_market
```

`assignment` — прежняя формула задания и режим по умолчанию.
`logit` — ценовая конкуренция с возможностью не покупать товар.
Для другого режима создаются новые политики; перенос таблиц и весов между
режимами блокируется. Начальные и промежуточные рыночные веса сохраняются
в `weights/`, по умолчанию каждые 50 эпизодов (`--checkpoint-every`).

В `runs/demo` сохраняются все политики в `agents.json`, метрики эпизодов
в `metrics.csv`, оценка без исследования и обучения на отдельных seed
в `evaluation.json`, оценки будущих коалиционных доходов в `coalition_values.json`.
`--load` без `--evaluate` продолжает обучение загруженных таблиц.
Оценивание не меняет исходные таблицы, счётчики обновлений и генераторы случайных чисел.

## Четыре разных агента

| ID | Алгоритм | Себестоимость | Начальный резерв |
|---|---|---:|---:|
| 0 | Q-learning | 1 | 80 |
| 1 | SARSA | 2 | 100 |
| 2 | Expected SARSA | 3 | 120 |
| 3 | Double Q-learning | 4 | 140 |

У каждого своя таблица, генератор случайных чисел и обновления по собственной
прибыли. Все используют `gamma=0.95`; вознаграждение при обучении делится на 100
для масштаба, в баланс поступают исходные денежные суммы.
SARSA использует действительно выполняемое следующее действие,
Expected SARSA — математическое ожидание по своей epsilon-greedy политике,
Double Q — две таблицы с раздельным выбором и оценкой следующего действия.

Действие: цена из `(2, 4, 6, 8, 10, 12)` и коалиционная метка `-1, 0, 1, 2, 3`.
Индекс действия: `price_index * 5 + coalition_label + 1`; `-1` означает работу
поодиночке. Агенты с одинаковой меткой объединяются в связные компоненты
индуцированного подграфа. Возможны пары, тройки и гранд-коалиция.
Наличие связи само по себе никого не включает в коалицию.

Локальное наблюдение содержит собственные издержки, резерв, прошлую награду и собственный штраф,
соседей, собственную предыдущую коалицию, историю своих связей и публичные цены.
Для табличного RL оно дискретизируется; полного графа у индивидуальной политики нет.
Правил вида «поднять цену при таком-то событии» нет: действия выбирают RL-политики.

## Коалиционный уровень и будущий доход

Общую цену выбирает **отдельная обучаемая коалиционная Q-политика**.
У каждого состава участников своя часть таблицы. Её цель:

\[
V_C^*(s)=\max_{\pi_C}\mathbb{E}\left[\sum_{t=0}^{T-1}
\gamma^t\sum_{i\in C}r_i^t\mid s\right],\qquad
\Delta_C(s)=V_C^*(s)-\sum_{i\in C}V_i^{solo}(s).
\]

Политика максимизирует совместный дисконтированный доход, включая будущие
штрафы и расходы на связи. Участие и выбор состава остаются решениями
индивидуальных агентов. Во время отсутствия данного состава участники могут
работать поодиночке или в других коалициях; эти доходы также входят в его
продолжение. При следующем появлении состава выполняется SMDP-обновление:

\[
Q_C(s,a)\leftarrow Q_C(s,a)+\alpha\left[
\sum_{k=0}^{d-1}\gamma^k R_C^{t+k}
+\gamma^d\max_{a'}Q_C(s',a')-Q_C(s,a)\right].
\]

При завершении эпизода продолжение равно нулю. Это учитывает реальное число
раундов между встречами, а не только прибыль последнего раунда.
Эталон `V_i^{solo}` обучается отдельно в копии рынка, где все работают
поодиночке. В этой копии тоже используются RL-политики четырёх агентов,
а не фиксированные цены. Это расчётный сценарий, дополнительных участников
в основном рынке нет. Коалиционный и одиночный сценарии используют одинаковый
дисконт и параметры рынка.

`max Q` — обучаемая оценка оптимума в выбранной дискретной модели.
Короткий прогон не доказывает сходимость, особенно при одновременно обучающихся
оппонентах. Для непосещённого коалиционного состояния выводится `null`.
Штрафы уже включены в доход и повторно из `Delta` не вычитаются.

**Денежные расчёты отделены от будущей ценности.** За текущий раунд участники
получают свою контрфактическую одиночную прибыль плюс долю реально полученного
коалиционного прироста. В контрфактическом расчёте цены внешних коалиций
фиксированы, а рассматриваемые участники используют свои индивидуальные
ценовые предложения. Подмножества могут исполнить собственную обученную
ценовую политику; если она не передана в среду — договор родительской коалиции.
Прирост может быть отрицательным. Его сумма точно совпадает с разницей
фактической и контрфактической прибыли; прогноз будущих денег на баланс не поступает.

Распределение текущего прироста: `equal`, `shapley`, `myerson`, `owen`.
Для четырёх участников перебор точный. Майерсон ограничивает игру графом;
Оуэн использует пересечения коалиций предыдущего раунда с текущим составом
как исторические блоки. Для первого раунда это одиночные участники.
Стратегическая оценка `V_C` и игра для текущего денежного распределения
хранятся раздельно.

## Среда и сеть

Один раунд: граф → выбор коалиций → общие/индивидуальные цены → рынок →
публичное наблюдение → действие внешнего арбитра → выплаты → следующий граф.

Для активных продавцов доли из сводки нормированы:

\[
w_i=\frac{1-p_i/\sum_jp_j}{m-1},\quad
P=\sum_iw_ip_i,\quad Q=\max(0,A-BP),\quad q_i=Qw_i.
\]

При одном продавце его доля равна 1, при отсутствии продавцов спрос не обслуживается.
Нормировка обеспечивает `sum(q_i)=Q`, а средневзвешенная цена обеспечивает
`sum(p_i*q_i)=P*Q`. Прибыль до переводов — `(p_i-c_i)*q_i`.
Потребительский излишек — `Q²/(2B)`, публичное `SW` — его сумма с операционной
прибылью. Штрафы считаются денежными переводами; расходы на образование сети
дополнительно вычитаются в метрике `net_welfare`.

В дополнительном logit-режиме `q_i=M*exp((v-p_i)/tau)/Z`, где
`Z=1+sum(exp((v-p_j)/tau))`, `M=demand_a`, а единица в знаменателе —
вариант отказа от покупки. `CS=M*tau*log(Z)`; `SW=CS+sum(profit)`.
По умолчанию `v=8`, `tau=1.5`; доступны `--logit-value` и `--logit-temperature`.
В этом режиме `demand_b` не используется для спроса. Вред коалиции оценивается
относительно точного конкурентного равновесия на сетке; исходный режим
сохраняет прежний критерий по индивидуальным предложениям.

Сеть симметрична, без петель. Доступны `complete`, `star`, `path`, `inner`
(две начальные пары) и `random`. Для случайной сети вероятность связи задаёт
логистическая функция квадратичного полинома сходства исходных признаков
со случайными воспроизводимыми весами. При эволюции учитываются исходное
сходство, прежнее наличие связи, история кооперации, полезность, оценка
выгоды по прошлым результатам и стоимость образования связи.
Формирование новой связи оплачивается её концами поровну, при наличии средств.
Начальные связи заданы стартовым сценарием и не оплачиваются повторно.

```bash
python3 -m market_rl.train --topology path --allocation myerson --output runs/path
python3 -m market_rl.train --topology inner --allocation owen --fixed-network --output runs/inner
```

По умолчанию участие фиксировано до банкротства, а связи меняются механизмом
среды; отдельного действия покупки/разрыва связи нет. Фиксация этих компонентов
допускается базовой постановкой. Прибыль изменяет резерв без обнуления убытков.
При достижении кредитного порога агент ограничен одиночной торговлей по цене
не ниже себестоимости. При отрицательном резерве `bankruptcy_patience` раундов
подряд он окончательно выбывает. `credit_limit=0` по умолчанию; временный
отрицательный резерв возможен после потерь/санкции и запускает ограничения.

## Подключение своего арбитра

`market_step(...)` возвращает неизменяемый
`PublicObservation`: цены с публичными ID, суммарный объём, среднюю цену, `SW`
и изменения цены/благосостояния. `settle(...)` принимает `ArbiterAction`:

- `ArbiterAction()` — наблюдение;
- `ArbiterAction("link_cost", amount=1.0)` — увеличить стоимость будущих связей;
- `ArbiterAction("sanction", amount=10.0, target=2)` — оштрафовать агента 2.

Стоимость влияет на вероятность **образования новых** связей и оплачивается
при их образовании. Существующие связи арбитр напрямую не удаляет.

```python
from market_rl.agents import load_agents, load_auxiliary
from market_rl.train import evaluate

config, agents = load_agents("runs/demo/agents.json")
coalition_policy, _ = load_auxiliary("runs/demo/agents.json")

# my_arbiter: ваша функция PublicObservation -> ArbiterAction
metrics = evaluate(config, agents, coalition_policy, episodes=1, arbiter=my_arbiter)
```

Для объекта арбитра `run_episode` автоматически вызывает `reset(seed, training)`
и, при наличии, `observe_transition` с публичными наблюдениями и скалярной
наградой. Для функции с памятью в замыкании сброс выполняет её владелец.
Граф, вероятности связей, истинные коалиции, себестоимости и приватные
истории в `PublicObservation` не передаются. Словарь `info` из `settle`
предназначен только для исследователя; передавать его арбитру нельзя.
При адаптации к новому арбитру следует переобучать и основные политики,
и одиночный эталон в условиях того же арбитра.

Поставляемый арбитр подключается флагом `--arbiter path/to/arbiter.json`;
обучение продавцов и обучение арбитра выполняются раздельно.

Код: `environment.py` — механика и граница арбитра; `agents.py` — четыре
индивидуальные политики; `coalition_policy.py` — будущий совместный доход;
`coalitions.py` — рынок и распределение; `train.py` — обучение и оценивание.
