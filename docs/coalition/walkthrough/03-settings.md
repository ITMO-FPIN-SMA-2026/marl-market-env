# Разбор 03 — Настройки

> [Разбор 00 — Оглавление](README.md) · предыдущая: [Разбор 02 — Как коалиция подключена к среде](02-environment-contract.md) · следующая: [Разбор 04 — Оракул ценности](04-value-oracle.md)
> Файл: `src/coalition_policy/settings.py`, 150 строк.

## Зачем нужен

ТЗ требует много экспериментов: разные структуры коалиций, способы деления, с памятью и без. Можно было бы написать отдельный класс на каждый режим, но тогда сравнение было бы нечестным: отличался бы не один параметр, а весь код.

Поэтому **политика одна, а режимы — это настройки**. Эксперимент меняет только `kwargs` в YAML.

## Как устроен

### Списки допустимых значений (строки 9–21)

```python
STRUCTURES = {'antagonism', 'partial', 'grand', 'adaptive'}
PAYOUTS = {'equal', 'shapley', 'myerson', 'owen', 'hybrid'}
PRICINGS = {'fixed', 'adaptive'}
PRICE_LEVELS = {'cautious': 0.05, 'moderate': 0.07, 'bold': 0.15, 'cartel': 1.0}
```

**Уровень цены задан падением SW, а не числом цены.** «Не больше 7 % падения» работает при любых $A$, $B$, $\tau$. Число цены вроде 27 пришлось бы пересчитывать для каждого рынка. Перевод уровня в цену — в части 07.

### Класс `PolicySettings` (строки 24–150)

`@dataclass(frozen=True)` — неизменяемая запись с полями. После создания поменять поле нельзя: настройки не могут случайно измениться посреди эпизода.

Метод `__post_init__` (строки 121–145) проверяет значения сразу при создании. Ошибка в YAML падает с понятным сообщением в начале эксперимента, а не непонятно где через 40 шагов.

## Все параметры

### Структура и деление (этап 1)

| Параметр | По умолчанию | Что делает | Где используется |
|---|---|---|---|
| `structure` | `adaptive` | Какие коалиции разрешены, см. ниже | Часть 05 |
| `payout` | `hybrid` | Схема деления котла | Часть 08 |
| `price_level` | `cartel` | Уровень цены. При адаптивной цене — только верхняя граница | Часть 07 |
| `partial_share` | 0.5 | В режиме `partial`: наибольшая группа — половина агентов | Часть 05 |
| `hysteresis` | 0.1 | Новый состав принимается, если выгоднее на 10 % | Часть 06 |
| `max_packings` | 32 | Сколько вариантов разбиения перебрать | Часть 06 |
| `max_evaluations` | 3 | Сколько лучших вариантов оценить точно | Часть 06 |
| `max_fresh_equilibria` | 2 | Сколько новых равновесий посчитать за шаг | Часть 12 |
| `max_exact_players` | 14 | Больше игроков — делим поровну: таблица $2^n$ слишком велика | Часть 08 |

**Режимы структуры:**

| Режим | Смысл | Эксперимент ТЗ |
|---|---|---|
| `antagonism` | Коалиций нет | «Полный антагонизм» |
| `partial` | Группы не больше половины агентов | «Частные коалиции» |
| `grand` | Только все вместе, если граф связный | «Гранд-коалиция» |
| `adaptive` | Любые группы, выбирает политика | Основной режим |

## Откуда взялись значения

Не все числа выбраны заранее. Часть исправлена по результатам экспериментов, и это видно в комментариях кода:

| Параметр | Было | Стало | Почему |
|---|---:|---:|---:|
| `ban_trust` | 0.5 | 0.3 | При 0.5 охват падал до 50 %, и прибыль снижалась |
| `discount` | 0.95 | 0.5 | При 0.95 оценка слишком любила мелкие группы, см. часть 12 |
| `partial_growth` | 1.0 | 1.1 | Небольшой рост помог на агентах, которые соблюдают частично |

## Проверка значений

`__post_init__` проверяет, что:

- строковые значения из допустимых списков;
- доли и коэффициенты в $(0,1]$;
- бандит включён только при адаптивной цене: он ограничивает лестницу, а без неё ограничивать нечего;
- коэффициенты роста не меньше 1, иначе «рост» был бы падением.

Тест `test_unknown_settings_are_rejected` проверяет, что неизвестная схема деления и неизвестный параметр вызывают ошибку.
