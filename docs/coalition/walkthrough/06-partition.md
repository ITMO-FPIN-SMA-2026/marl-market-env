# Разбор 06 — Выбор разбиения

> [Разбор 00 — Оглавление](README.md) · предыдущая: [Разбор 05 — Кандидаты](05-candidates.md) · следующая: [Разбор 07 — Цена](07-pricing.md)
> Файл: `src/coalition_policy/structure.py`, 63 строки.

## Зачем нужен

Кандидаты часто пересекаются: компонента $\{1,2,3,4\}$ и её сообщества $\{1,2\}$ и $\{3,4\}$ — три кандидата, но взять можно либо первую, либо две последние. Этот модуль решает, **какой набор непересекающихся групп** получит планы.

## Теория: упаковка множеств

Задача «выбрать непересекающиеся множества с наибольшей суммарной ценностью» называется **упаковкой множеств** (set packing). В общем случае она NP-трудная: перебор растёт экспоненциально. Но кандидатов у нас немного, обычно меньше 10, поэтому перебор с ограничением работает.

**Максимальная упаковка** — та, к которой нельзя добавить ни одной группы без пересечения. Немаксимальные упаковки смысла рассматривать нет: добавление ещё одной коалиции не мешает остальным, а свободные агенты превратились бы в безбилетников.

## Шаг 1. Перебор: `maximal_packings` (строки 13–32)

Рекурсивный перебор:

```text
extend(с какого кандидата начинать, выбранные группы, занятые агенты):
    свободные = кандидаты дальше по списку, не пересекающиеся с занятыми
    если свободных нет:
        если ни один кандидат во всём списке не помещается — упаковка максимальная, сохранить
        выйти
    для каждого свободного:
        extend(следующий после него, выбранные + он, занятые + его агенты)
```

Проверка в строке 25 тонкая. Кандидат, **пропущенный раньше**, мог бы ещё поместиться. Тогда упаковка не максимальная, и она не сохраняется.

Крупные группы стоят в начале списка (строка 16), поэтому перебор быстрее находит упаковки с большим охватом. После `limit` найденных упаковок перебор останавливается: по умолчанию 32.

**Пример.** Кандидаты: $\{0,1\}$, $\{1,2\}$, $\{2,3\}$, $\{0,1,2,3\}$.

| Упаковка | Максимальная? |
|---|---|
| $\{0,1,2,3\}$ | Да |
| $\{0,1\}$, $\{2,3\}$ | Да |
| $\{1,2\}$ | Да: $\{0,1\}$ и $\{2,3\}$ пересекаются с ней |
| $\{0,1\}$ | Нет: можно добавить $\{2,3\}$ |

Это ровно тест `test_packings_are_disjoint_and_maximal`.

## Шаг 2. Дешёвый отбор: `coverage_rank` (строки 35–41)

Точная оценка упаковки дорогая: нужно равновесие (часть 04). Поэтому сначала упаковки сортируются по дешёвому признаку:

$$\text{ранг}=\Bigl(\ \underbrace{\textstyle\sum_C |C|}_{\text{охват}},\ \underbrace{\textstyle\sum_C |C|^2}_{\text{крупность}}\ \Bigr)$$

Сравнение идёт сначала по охвату, при равенстве — по крупности.

**Почему охват.** Безбилетник вне коалиции зарабатывает больше участника (часть 01). Чем больше агентов в каких-нибудь группах, тем меньше безбилетников.

**Почему квадрат размера.** Ценность коалиции растёт быстрее её размера: 6 агентов вместе стоят больше, чем 3 + 3. Сумма квадратов при равном охвате предпочитает крупные группы: $6^2=36>3^2+3^2=18$.

В точную оценку попадают `max_evaluations` лучших, по умолчанию 3.

## Шаг 3. Точная оценка

Функция `score` приходит снаружи, из `policy.py`. Это сумма оценок групп $V(C)$, учитывающая цены, доверие, штрафы и выживание связей. Подробно — в [Разбор 12 — Сборка](12-policy-assembly.md). Здесь важно одно: выбирается упаковка с наибольшим `score`.

## Шаг 4. Гистерезис (строки 57–63)

**Гистерезис** — «инерция решения»: состояние меняется, только если причина достаточно сильна. Термостат не включается и не выключается каждую секунду: он включается при 19°, а выключается при 21°.

Здесь: если прошлое разбиение ещё возможно, все его группы есть среди кандидатов, оно остаётся, пока новое не выгоднее заметно:

$$\text{сменить, только если}\quad \text{score}(\text{новое}) > \text{score}(\text{прошлое})+0.1\cdot|\text{score}(\text{прошлое})|$$

**Зачем.** Память кооперации $H_{ij}$ растёт только у пар, которые соблюдали план **вместе**. Частая смена состава обнуляет её, связи слабеют, и группа хуже переживает давление арбитра. Ещё одна причина: у постоянного состава постоянный номер плана, и историю соблюдения проще связать с группой.

**Пример** из теста `test_hysteresis_keeps_previous_partition`: прошлое разбиение даёт 100, новое 105. 105 не больше $100+0.1\cdot100=110$, значит, остаёмся. Если новое даёт 120, переходим.

## Особый случай: бюджет равновесий

Политика за шаг считает не больше двух **новых** равновесий (`max_fresh_equilibria`). Если упаковку нельзя оценить без нового равновесия, а бюджет исчерпан, её оценка равна $-\infty$, и она проигрывает. Подробнее — в части 12.

Если оценка прошлого разбиения тоже $-\infty$, формула гистерезиса даёт неопределённость (NaN). Сравнение с NaN в Python всегда ложно, поэтому выбирается новое. Это работает, но держится на тонком свойстве арифметики.

## Ограничения

- Перебор ограничен 32 упаковками, и при многих кандидатах лучшая может в них не попасть. Крупные группы идут первыми, поэтому обычно попадает.
- Точно оцениваются только 3 упаковки из найденных.
- Порог гистерезиса 10 % выбран без отдельного эксперимента.
