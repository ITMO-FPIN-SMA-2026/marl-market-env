> Файл: `src/coalition_policy/payouts.py`, 213 строк. Самая насыщенная теорией часть.

## Зачем нужен

Среда делит котёл группы по весам $w_i$, которые задаёт коалиция (часть 02, раздел 7). От весов зависит, выгодно ли агенту оставаться: если он получает меньше, чем заработал бы обманом, он обманет.

**Главный экспериментальный результат проекта касается именно этого модуля:** при равном делении удерживаемая прибыль в 2.4–2.8 раза ниже, чем при делении по вкладу. Например, 55.7 против 133.8 на цепочке.

Причина: при равном делении дешёвый продавец получает меньше своего вклада. Ему выгоднее уйти, ограничение на соблазн (часть 07) срабатывает раньше, и политике приходится снижать цену для всех.

ТЗ требует четыре способа деления: поровну, Шепли, Майерсон, Оуэн. Пятый, гибрид, — наш.

## 1. Какую игру делим: `level_game` (строки 27–54)

Чтобы делить «по вкладу», нужно знать ценность каждого подмножества — характеристическую функцию $v(S)$ (часть 01, раздел 6).

**Почему не взять $v$ из среды.** Её `CharacteristicFunction` считает ценность при **картельной** цене. А наша политика обычно назначает умеренную цену (часть 07). Доли, посчитанные для одних цен, не соответствуют котлу при других.

Поэтому своя игра — **игра запланированных цен** $v_\ell$:

$$v_\ell(S)=\max\Bigl(\sum_{i\in S}\pi_i\bigl(p^{S}\bigr),\ \sum_{i\in S}\pi_i^{N}\Bigr)$$

где $p^S$ — цены, при которых:

- участники $S$ держат цены плана;
- остальные участники того же плана вернулись к Нэшу (будто ушли из коалиции);
- продавцы вне плана держат свои цены.

**Зачем нижняя граница по Нэшу.** Если план с высокой ценой, маленькое подмножество, держащее её в одиночку, почти ничего не продаст: $\pi\approx0$. Но подмножество всегда может просто вернуться к конкуренции и получить свой Нэш. Без этой границы малые подмножества выглядели бы бесполезными, и деление было бы искажено.

**Скорость.** Для каждого из $2^n$ подмножеств нужен только один прогон рынка, без равновесий. Все $2^{12}=4096$ прогонов делаются одной матричной операцией NumPy: строка матрицы — одно подмножество (строки 46–54). Это миллисекунды.

## 2. Битовые маски: как записать подмножество числом

У группы из $n$ игроков ровно $2^n$ подмножеств. Каждое удобно записать числом: бит $k$ равен 1, если игрок $k$ входит.

| Игроки $[3,5,7]$ | Маска | Двоичная | Подмножество |
|---|---:|---|---|
| | 0 | `000` | $\varnothing$ |
| | 1 | `001` | $\{3\}$ |
| | 5 | `101` | $\{3,7\}$ |
| | 7 | `111` | $\{3,5,7\}$ |

Нужные трюки:

| Операция | Код | Смысл |
|---|---|---|
| Входит ли игрок $k$ | `(mask >> k) & 1` | Сдвинуть и взять младший бит |
| Добавить игрока $k$ | `mask \| (1 << k)` | Включить бит |
| Убрать часть | `mask ^ part` | Выключить биты части |
| Младший игрок | `mask & -mask` | Оставляет только младший единичный бит |
| Все подмножества маски | `sub = (sub - 1) & mask` | Перебор подмасок, `_submasks` |

Таблица ценностей — массив длины $2^n$: `values[mask]` $=v(\text{подмножество})$. Матрица `_membership` (строки 175–177): строка — маска, столбец — игрок, истина если игрок входит.

## 3. Вектор Шепли: `shapley_table` (строки 57–67)

### Идея

Агенты приходят в коалицию по одному в случайном порядке. Каждый получает свой **маржинальный вклад**: насколько выросла ценность с его приходом. Вектор Шепли — средний вклад по всем порядкам:

$$\varphi_i=\sum_{S\subseteq N\setminus\{i\}}\frac{|S|!\,(n-|S|-1)!}{n!}\,\bigl[v(S\cup\{i\})-v(S)\bigr]$$

Вес $\frac{|S|!(n-|S|-1)!}{n!}$ — доля порядков, в которых перед $i$ пришло ровно множество $S$.

### Свойства

Шепли — единственное правило с четырьмя свойствами:

| Свойство | Смысл |
|---|---|
| Эффективность | $\sum\varphi_i=v(N)$: делится всё |
| Симметрия | Одинаковые по вкладу получают поровну |
| Болван | Кто ничего не добавляет, получает 0 |
| Аддитивность | Деление суммы игр — сумма делений |

### Пример из `Шепли.docx`

$v(1)=1$, $v(2)=2$, $v(3)=1$, $v(12)=5$, $v(13)=7$, $v(23)=6$, $v(123)=10$.

Для игрока 1 при $n=3$ веса: пустое $S$ — 1/3, одиночка — 1/6, пара — 1/3:

$$\varphi_1=\tfrac13(1-0)+\tfrac16(5-2)+\tfrac16(7-1)+\tfrac13(10-6)=\tfrac{2+3+6+8}{6}=\tfrac{19}{6}$$

Итог: $\Phi=(19/6,\ 19/6,\ 22/6)\approx(3.17,\ 3.17,\ 3.67)$.

### Как считает код

Для каждого игрока берутся все маски без него, `without`, и векторно:

```python
result[player] = weights[sizes[without]] @ (values[without | (1 << player)] - values[without])
```

Это ровно формула выше, только вместо цикла по подмножествам — одно скалярное произведение. Тест `test_shapley_matches_lecture_example` проверяет пример из docx, а `test_fast_shapley_matches_environment_library` — совпадение с медленной версией среды.

## 4. Вектор Майерсона: Шепли с учётом сети

### Идея

Шепли считает, что сотрудничать могут любые агенты. Но у нас договариваться можно только по связям. **Майерсон** (1977): несвязанное подмножество стоит столько, сколько его связные части по отдельности.

$$v^G(S)=\sum_{K\ -\ \text{связная часть }S}v(K),\qquad \mu_i=\varphi_i(v^G)$$

### Пример: цепочка 1 — 2 — 3

Пусть $v$ одиночки 0, любой пары 2, всех троих 6. По Шепли всем поровну: 2, 2, 2.

На цепочке пара $\{1,3\}$ не связана, поэтому $v^G(\{1,3\})=v(1)+v(3)=0$. Остальное без изменений. Для игрока 1:

$$\mu_1=\tfrac13\cdot0+\tfrac16\cdot(2-0)+\tfrac16\cdot(0-0)+\tfrac13\cdot(6-2)=\tfrac13+\tfrac43=\tfrac53$$

Симметрично $\mu_3=5/3$, и $\mu_2=6-10/3=8/3$.

**Средний агент получает больше**: без него крайние не могут договориться. Майерсон платит за **позицию в сети**. Тест `test_weights_are_valid_and_center_of_star_gets_more` проверяет то же на звезде.

### Как считает код: `restrict_to_graph` (строки 70–83)

1. Для каждого игрока маска его соседей, `neighbors`.
2. Для каждой маски находится связная часть младшего игрока, `_component` (строки 184–193): обход в ширину на битах. Начать с младшего бита, добавлять соседей, пока появляются новые.
3. Тогда $v^G(\text{mask})=v(\text{часть})+v^G(\text{mask без части})$. Маска без части меньше самой маски, поэтому её значение уже посчитано. Это **динамическое программирование**: каждый ответ собирается из уже готовых.

Версия среды на 12 игроках работала 2.1 с, эта — миллисекунды.

## 5. Вектор Оуэна: деление с учётом союзов

### Идея

Иногда коалиция собирается из групп, которые уже сотрудничали раньше: **априорных союзов**. Оуэн (1977) делит в два уровня:

1. Союзы делят общую ценность между собой как игроки (по Шепли).
2. Внутри союза доля делится между его участниками.

Формально — Шепли, но усреднённый только по тем порядкам, где участники одного союза приходят подряд.

### Пример из `Шепли.docx` с союзами $\{1,2\}$ и $\{3\}$

**Верхний уровень.** Союз $U=\{1,2\}$ стоит 5, союз $\{3\}$ — 1, вместе 10. Шепли для двух игроков:

$$U:\ \tfrac12\bigl(5+(10-1)\bigr)=7,\qquad \{3\}:\ \tfrac12\bigl(1+(10-5)\bigr)=3$$

**Внутри $U$.** Для игрока 1 усредняем по тому, пришёл ли союз $\{3\}$ раньше:

- союз 3 не пришёл: $\tfrac12(1-0)+\tfrac12(5-2)=2$;
- союз 3 пришёл: $\tfrac12(7-1)+\tfrac12(10-6)=5$;
- итог $\tfrac12(2+5)=3.5$.

Получается $\text{Оуэн}=(3.5,\ 3.5,\ 3)$, сумма 10. Союз защитил игрока 2: у него 3.5 против 3.17 по Шепли.

### Как считает код: `owen_table` (строки 86–112)

Для игрока из союза $B$ нужны все объединения **других** союзов (`_unions_of`) и все подмножества **своего** союза без себя (`_submasks`). Матрица вкладов умножается на внешние веса слева и внутренние справа:

```python
result[player] = outer_weight[outer_sizes] @ gains @ inner_weight[inner_sizes]
```

Тест `test_owen_matches_environment_library` сверяет с версией среды. `test_owen_with_singleton_unions_is_shapley` проверяет, что если каждый союз из одного игрока, Оуэн совпадает с Шепли, как и должно быть по определению.

### Откуда берутся союзы

`policy.py` запоминает их при первом появлении группы (`_remember_unions`, часть 12). Если новая группа собрана из прошлых, её союзы — пересечения с прошлыми группами размером от двух.

## 6. Ядро: деление, от которого никто не уйдёт

### Определение

**Ядро** — все дележи $x$, при которых никакой подгруппе не выгодно отделиться:

$$\sum_{i\in S}x_i\ \ge\ v(S)\quad\text{для всех }S,\qquad\sum_{i\in N}x_i=v(N)$$

**Претензия** подгруппы $S$: $e(S)=v(S)-\sum_{i\in S}x_i$. Если претензия положительна, подгруппа получает меньше, чем могла бы сама, и ей выгодно уйти. `core_excess` (строки 139–144) возвращает наибольшую претензию.

### Шепли может не лежать в ядре

В примере из docx подгруппа $\{1,3\}$ стоит 7, а по Шепли получает $19/6+22/6=41/6\approx6.83$. Претензия $1/6$: **Шепли неустойчив**. Это проверяет тест `test_lecture_shapley_is_outside_the_core_and_projection_fixes_it`.

### Проекция на ядро: `project_to_core` (строки 115–136)

Простой алгоритм:

```text
повторить до 200 раз:
    найти подгруппу S с наибольшей претензией e
    если e ≤ 0 — дележ в ядре, готово
    добавить e/|S| каждому в S
    отнять e/(n−|S|) у каждого вне S
```

После шага подгруппа $S$ получает ровно $v(S)$, а сумма не меняется.

**Пример.** Старт — Шепли $(3.17,\ 3.17,\ 3.67)$. Наибольшая претензия у $\{1,3\}$, $e=1/6$: игрокам 1 и 3 по $+1/12$, игроку 2 $-1/6$. Получается $(3.25,\ 3.00,\ 3.75)$. Проверка: $\{1,2\}=6.25\ge5$, $\{1,3\}=7\ge7$, $\{2,3\}=6.75\ge6$. Дележ в ядре.

### Ядро бывает пустым

Игра большинства: любые двое из трёх получают 1, все трое — тоже 1. Чтобы каждая пара получала не меньше 1, нужно $x_1+x_2\ge1$, $x_1+x_3\ge1$, $x_2+x_3\ge1$. Сложив: $2(x_1+x_2+x_3)\ge3$, а сумма всего 1. Противоречие, ядро пусто.

В этом случае код возвращает лучший найденный дележ: с наименьшей максимальной претензией. Тест `test_projection_with_empty_core_keeps_total_and_improves`.

## 7. Гибрид — наш способ деления

ТЗ разрешает свой механизм, «если он повышает устойчивость или суммарный бонус». Гибрид (строки 147–157) — три шага:

1. **Майерсон** на игре запланированных цен: учитывает и вклад, и позицию в сети.
2. **Проекция на ядро** игры Майерсона: никакой связной подгруппе не выгодно уйти.
3. **Страховка**: к выплате оштрафованного раньше участника добавляется часть его штрафа (часть 10).

### Что показали эксперименты

| Схема | `cartel`, цепочка | Нарушение ядра |
|---|---:|---:|
| Поровну | 55.7 | 15.1 % котла |
| Шепли | 133.8 | 0 |
| Майерсон | 133.8 | 0 |
| Оуэн | 65.8 | 0 |
| Гибрид | 133.8 | 0 |

Честно о результате: **гибрид совпал с Майерсоном**. На нашей игре Майерсон уже лежит в ядре, и проекции нечего исправлять. Похоже, игра близка к **выпуклой** ($v(S\cup\{i\})-v(S)$ растёт с ростом $S$), а для выпуклых игр Шепли всегда в ядре. Но это наблюдение, а не доказательство. Страховка в этих прогонах не проверялась, потому что арбитр не штрафовал.

Оуэн на цепочке заметно хуже, и причина пока не выяснена.

## 8. Из выплат в веса: `payout_weights` (строки 160–172)

Среде нужны веса: неотрицательные и в сумме 1. Функция `to_weights` из среды отрезает отрицательные значения и нормирует. Если всё нулевое, делит поровну. Надбавка страховки добавляется к выплате **до** нормировки.

## Ограничения

- Точный счёт требует таблицы $2^n$. При $n>14$ политика делит поровну (часть 12). В ЛР $N=12$, поэтому это не мешает.
- Проекция на ядро — эвристика, а не точный алгоритм наименьшего ядра.
- Игра $v_\ell$ считает, что ушедшие из плана возвращаются к Нэшу, а остальные продавцы не меняют цен. Это упрощение.
