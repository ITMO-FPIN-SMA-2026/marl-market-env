## Зачем нужен

Чтобы сравнивать варианты коалиций, политике постоянно нужны ответы на вопросы:

- Какие цены были бы при честной конкуренции? Это точка отсчёта.
- Какие цены были бы, если эти группы действуют как картели?
- Насколько участники заработают больше, чем при конкуренции?

Первые два ответа требуют **равновесия** (часть 01, раздел 3), а оно считается 10–80 мс. На один шаг политики отведено около 200 мс. Без запоминания результатов политика не уложилась бы во время.

**Оракул** — модуль, который отвечает на эти вопросы и запоминает ответы.

## Теория: равновесие разбиения

Пусть агенты разбиты на группы, и каждая группа действует как один игрок, максимизируя свою общую прибыль:

$$\max_{p_i,\ i\in G}\ \sum_{i\in G}\pi_i(p)\qquad\text{для каждой группы }G$$

Агенты вне групп — сами по себе. **Равновесие разбиения** — цены, при которых ни одной группе не выгодно менять цены своих участников. Среда считает его функцией `group_equilibrium`: те же осторожные наилучшие ответы, только теперь отвечает группа, перебирая цены участников по очереди.

### Почему считать всё разбиение сразу

Можно было бы посчитать каждую группу отдельно, считая остальных одиночками, и сложить. Это неверно: **планы влияют друг на друга**. Когда одна группа поднимает цену, покупатели уходят к другим, и те выигрывают.

Пример из расчёта плана, 12 одинаковых агентов:

| Разбиение | Сумма по группам отдельно | Всё разбиение вместе |
|---|---:|---:|
| Две группы по 6 | 2 × 27 = 54 | 351 |

Отдельно каждая группа из шести почти бесполезна: остальные шесть одиночек отбирают у неё покупателей. Вместе две группы по шесть уже никого не боятся. Разница в 6.5 раза.

## Как устроен код

### Типы (строки 18–25)

```python
CostKey = frozenset[tuple[int, float]]   # набор (агент, себестоимость)
Group = frozenset[int]                   # группа агентов
Partition = tuple[Group, ...]            # разбиение
```

`frozenset` — неизменяемое множество. Его можно использовать как ключ словаря, а обычное `set` нельзя.

`canonical(partition)` сортирует группы, чтобы одно и то же разбиение, записанное в разном порядке, давало один ключ: $(\{1,2\},\{3,4\})$ и $(\{3,4\},\{1,2\})$ — одно разбиение.

### `ValueOracle` (строки 28–65)

| Метод | Что возвращает | Кэш |
|---|---|---|
| `nash(costs)` | Равновесие Нэша для набора себестоимостей | `_nash` |
| `partition_equilibrium(costs, partition)` | Равновесие разбиения: группы как картели, остальные одиночки | `_partitions` |
| `knows(costs, partition)` | Посчитано ли уже это разбиение | — |
| `gain(costs, prices, members)` | $\sum_{i\in\text{members}}(\pi_i(\text{prices})-\pi_i^{\text{Нэш}})$ | — |

### Почему ключ кэша — себестоимости

В ключ входит набор `(агент, себестоимость)`, а не номер эпизода. Это даёт два удобных свойства:

1. **Кэш живёт между эпизодами.** Себестоимости в пределах одного seed не меняются, и посчитанное в первом эпизоде пригодится во втором.
2. **Кэш сам «сбрасывается» при выбывании.** Если агент выбыл, набор активных себестоимостей другой, ключ другой, и старые результаты просто не используются. Никакой ручной очистки.

## Пример

Себестоимости 12 агентов, разбиение $(\{0,1,2,3,4,5\},\{6,\dots,11\})$:

1. Первый вызов `partition_equilibrium` — около 50 мс, результат записывается.
2. Следующие вызовы с тем же разбиением — мгновенно.
3. `gain(costs, prices, members={0..5})` прогоняет рынок при данных ценах и вычитает прибыли Нэша: на сколько первая группа заработала больше конкуренции.

## Внешняя опция участника

В плане проекта внешняя опция $o_i$, то есть что агент получит без коалиции, определялась как лучшее из прибыли Нэша и прибыли безбилетника. В коде она проще: **прибыль по Нэшу**.

Почему это допустимо (строки 7–9 в docstring):

- разовую выгоду обманщика отдельно учитывает соблазн $T_i$ (часть 07);
- после обмана лестница цены опускает цену группы, так что дальше обманщик действительно получает около Нэша.

## Ограничения

- Равновесие ищется перебором по сетке, точность около 0.01.
- Первый расчёт нового разбиения дорогой, поэтому политика ограничивает их число за шаг (`max_fresh_equilibria`, часть 12).
- Кэш растёт без ограничения. Для 12 агентов это не проблема, но для сотен разных разбиений за эпизод понадобилось бы ограничение.
