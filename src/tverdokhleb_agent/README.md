# TverdokhlebAgent

Самостоятельный рыночный агент для `social_market_env`, контракт `2.0.0`.
Структура пакета следует примеру `askarov_agent`: публичный класс,
`agent.py`, `experiment.py`, собственные YAML и тесты.

## Установка и подключение

Из корня проекта, Python >=3.11:

```bash
python -m pip install -e '.[dev]'
python -m social_market_env.run experiments/tverdokhleb_agent.yaml
```

В YAML наш агент занимает позицию `0` среди пяти продавцов. Остальные агенты,
коалиционная политика и арбитр — штатные компоненты среды. Этот запуск проверяет
подключение без обучения и без чекпойнта; в неизвестных состояниях работает
резервная стратегия. Размер рынка можно изменить в YAML, согласовав overrides.

В своей конфигурации используйте:

```yaml
agents:
  overrides:
    0:
      impl: "tverdokhleb_agent:TverdokhlebAgent"
      kwargs:
        config: {state_mode: history}
```

Параметры рынка передаёт штатный загрузчик. Дополнительных зависимостей,
регистрации в ядре или изменений `pyproject.toml` не требуется.

## Обучение и оценка

```bash
python -m tverdokhleb_agent.experiment train
python -m social_market_env.run runs/tverdokhleb_agent/policy.eval.yaml
```

По умолчанию выполняются 300 эпизодов по 100 шагов. Один экземпляр агента
сохраняет Q-таблицу, а новый корневой seed для каждого эпизода изменяет издержки
и сеть. Сценарии циклически перебирают четыре топологии, статическую/динамическую
сеть и четыре состава рынка: конкуренцию, кооперацию, санкции и смешанный базовый
сценарий. Seed обучения: 42–341; оценки: 100000–100002.

Контролируется число фактически полученных переходов. Если за указанные эпизоды
получено менее `--min-updates` (по умолчанию 10000), команда завершается ошибкой
и сохраняет диагностический отчёт. В нём есть выживание, число обновлений,
конечный epsilon, себестоимость и результат каждого эпизода. Общий горизонт
рынка не выдаётся за число шагов обучаемого агента.

Результаты находятся в `runs/tverdokhleb_agent/`:

- `policy.json` — переносимая Q-таблица, настройки и фактические seed обучения;
- `policy.training.json` — протокол и результаты обучения;
- `policy.eval.yaml` — готовая конфигурация штатного раннера с загрузкой модели.

CLI поддерживает `--config`, `--agent-id`, `--horizon`, `--episodes`,
`--min-updates`, `--seed`, `--state-mode`, `--eval-seeds` и `--output`.
Проверочные seed не должны пересекаться с обучающими. Относительные пути в
сгенерированном YAML разрешаются от рабочей папки: запускайте команды из корня
проекта. Native runner также может обучать агента с `mode: train`, но сохраняет
издержки в пределах одного корневого seed и создаёт новую модель для следующего.
Для общего обучения на разных рынках предназначен именно `experiment train`.

## Сравнение и эффект памяти

```bash
python -m tverdokhleb_agent.experiment benchmark
```

Команда обучает `context` и `history` по отдельности с начальными seed
42, 1042, 2042, затем оценивает их на новых seed и всех 32 сочетаниях сценария,
топологии и режима сети. В каждой проверочной ситуации одинаковы издержки и
seed сброса для всех сравниваемых политик. Дополнительно проверяются агент
без обучения с той же резервной стратегией и штатный `BestResponseAgent`.
В оценке Q-таблицы и метаданные заморожены.

Все различия `context` и `history` ограничены двумя историческими признаками;
пространство действий, текущая рыночная информация и гиперпараметры совпадают.
Такое сравнение отделяет эффект памяти от добавления себестоимости и резервов.
Старый минимальный вариант можно включить через `--variants basic context history`.
Параметры `--train-seeds` и `--eval-seeds` задают независимые обучения и общие
проверочные ситуации; блоки обучающих seed не должны пересекаться.

В `runs/tverdokhleb_agent/benchmark/` сохраняются модели каждого повтора,
отчёты обучения, `comparison.json` с отдельными эпизодами и `comparison.md`.
Фиксируются награды, выживание, штрафы, участие в коалициях, благосостояние и
доля известных состояний. Известное состояние означает наличие строки Q, а не
достаточное изучение всех её действий. Разница history−context приводится отдельно
для каждого обучения; эпизоды разных сценариев не объявляются независимыми
повторами обучения и автоматически статистическая значимость не заявляется.

### Проверенный результат

Запуск протокола по умолчанию 05.11.2026: три независимых обучения каждого
варианта по 300 эпизодов, 32 условия × 3 проверочных seed для каждого обучения.
Все шесть моделей получили 29941–30000 обновлений и достигли epsilon 0,05.

| Политика | Средняя суммарная награда за эпизод | Выживание | Известные состояния |
|---|---:|---:|---:|
| context | 45601,85 | 100% | 99,98% |
| history | 54296,97 | 100% | 99,93% |
| Без обучения | 23350,44 | 100% | 0% |
| BestResponse | 71638,20 | 100% | — |

Средняя разница history−context по трём обучениям: +796,14; −673,58; +25962,79.
Память улучшила общий средний результат, но эффект нестабилен между обучениями;
устойчивое преимущество памяти этим экспериментом не доказано. BestResponse
пока сильнее обоих обученных вариантов. Артефакты можно воспроизвести командой
выше; модели и подробные отчёты сохраняются в игнорируемой папке `runs/`.

Отдельная проверка первого history-чекпойнта на исходном `random/evolving`
YAML и seed 100000–100002 дала 98,33% известных состояний и 100% выживания,
но среднюю награду 10957,49 против 22897,55 без обучения и 29444,61 у
BestResponse. Модель взята из первого повтора, без отбора по проверочной награде.
Здесь улучшенное покрытие не привело к лучшей политике; преимущество из общей
таблицы нельзя переносить на каждый состав рынка. Штатный раннер успешно
выполнил эти эпизоды, не изменив файл модели.

## Политика

Табличный Q-learning выбирает цену из сетки (33 уровня по умолчанию), принятие
предложения коалиции по точной рекомендованной цене или пропуск торговли.
Недопустимые действия исключаются при выборе и в следующем Q-максимуме.
Награда поступает от среды после распределения прибыли и штрафов.

По умолчанию агент не предлагает цену ниже собственной себестоимости и не
принимает такое предложение коалиции. Это предотвращает ранние банкротства при
случайном исследовании, но может исключать полезное коалиционное субсидирование.
Ценовые войны доступны через `config: {allow_loss_leading: true}`; ограничения
отрицательного резерва остаются обязательными. Штрафы и коалиционные выплаты
могут приводить к убыткам даже при неотрицательной индивидуальной марже.

В неизвестном состоянии eval выбирается ближайшая к `cost + 5` цена среди цен
не ниже себестоимости. Если такой цены нет, агент пропускает торговлю.
Это правило действует и при `allow_loss_leading: true`. Запросы на изменение
связей агент не отправляет (`link_action=None`).

Представления состояния:

- `basic`: средняя цена, наличие соседей, ограничение резерва, наличие предложения;
- `context`: дополнительно себестоимость, резерв, маржа предложения и доля выплаты;
- `history`: все признаки context плюс динамика средней цены и недавние награды.

В `reset` очищается память эпизода, сохраняются Q-таблица и счётчик обновлений.
В оценке epsilon равен нулю, память продолжает обновляться. Равные Q-значения
разрешаются генератором с seed. Используются только наблюдения агента и
публичные параметры рынка.

## Модели и проверки

```bash
python -m pytest -q tests/test_tverdokhleb_agent.py
python -m pytest -q
```

Формат JSON — версия 3, контракт среды — по-прежнему 2.0.0. Старые модели
QLearningAgent/MVP требуют переобучения: изменилась политика допустимых действий.
`model_path` загружает настройки и таблицу; одновременно передавать `config`
нельзя. В library/native-режиме `checkpoint_path` сохраняет модель после
терминального перехода при обучении, поддерживая `{agent_id}` и `{seed}`.
Оценка файл модели не меняет. Продолжить обучение можно загрузкой через
`model_path` и последующим `reset(..., training=True)`; CLI train начинает новый
независимый запуск.

Эксперименты этого пакета относятся к отдельному рыночному агенту. Они не заменяют
три совместных цикла адаптации с обучаемым арбитром и общую презентацию команды.
