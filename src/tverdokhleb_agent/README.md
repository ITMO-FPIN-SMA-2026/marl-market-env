# TverdokhlebAgent

Рыночный агент на табличном Q-learning с короткой памятью, контракт среды `2.0.0`.
Публичный класс: `tverdokhleb_agent:TverdokhlebAgent`. Ядро среды и зависимости не меняются.

## Запуск

Команды выполняются из корня проекта в активированном Python-окружении (>=3.11):

```bash
python -m pip install -e '.[dev]'
python -m social_market_env.run experiments/tverdokhleb_agent.yaml
```

Этот YAML проверяет подключение **без обученной модели**: агент 0 использует
резервную цену, ближайшую к `cost + 5` в допустимой сетке. Всего в примере пять продавцов.

## Обучение и оценка

```bash
python -m tverdokhleb_agent.experiment train
python -m social_market_env.run runs/tverdokhleb_agent/policy.eval.yaml
python -m tverdokhleb_agent.experiment evaluate
```

`train` начинает новую Q-таблицу: 300 эпизодов по 100 шагов, seed 42–341.
Один агент сохраняет опыт между эпизодами с новыми издержками. Минимум 10000
фактических переходов (`--min-updates`); при недоборе команда сохраняет отчёт и завершается ошибкой.
Выход: `policy.json`, `policy.training.json` и готовый `policy.eval.yaml` в `runs/tverdokhleb_agent/`.

Обучение циклически перебирает 32 условия: `competition/cooperation/sanctions/mixed`,
`complete/star/path/inner_coalitions`, `static/evolving`. `--config` задаёт базовый YAML,
но топология и режим сети заменяются; только `mixed` сохраняет его соперников, коалиции и арбитра.

`evaluate` загружает чекпойнт и сравнивает его с необученным агентом и `BestResponse`
на **исходном YAML**, сохраняя сеть, соперников, коалиции и арбитра. Seed оценки: 100000–100002.
Все политики получают одинаковые издержки и seed сброса, обучение отключено.
Результаты: `evaluation.json` и `evaluation.md`, включая разбивку по сценариям.

```bash
# Другой чекпойнт; --suite matrix вместо base проверяет все 32 условия
python -m tverdokhleb_agent.experiment evaluate --checkpoint runs/tverdokhleb_agent/benchmark/repeat_0/history.json
# Короткая проверка запуска, не полноценное обучение
python -m tverdokhleb_agent.experiment train --episodes 4 --horizon 5 --min-updates 10 --output runs/tverdokhleb_agent/smoke/policy.json
```

Общие параметры: `--config`, `--agent-id`, `--horizon`, `--eval-seeds`, `--output`.
Остальные доступны через `<команда> --help`. Проверочные seed не должны пересекаться с обучающими.
Пути к модели разрешаются от рабочей папки. Для подключения в своём YAML:

```yaml
agents:
  overrides:
    0:
      impl: "tverdokhleb_agent:TverdokhlebAgent"
      kwargs: {model_path: "runs/tverdokhleb_agent/policy.json"}
```

`model_path` загружает настройки и Q-таблицу, поэтому вместе с ним нельзя задавать `config`.
Формат модели — v3; старые MVP/v2 требуют переобучения, параметры рынка должны совпадать.
Native runner поддерживает `mode: train` и `kwargs.checkpoint_path` с `{agent_id}`/`{seed}`:
сохранение происходит после терминального перехода. Он создаёт нового агента для каждого
корневого seed; для общего обучения на разных рынках используйте `experiment train`.

## Как работает агент

**Действия.** По умолчанию 33 равномерные цены: `p_i = p_min + i × (p_max − p_min) / 32`, `i=0…32`.
При диапазоне 1–100 шаг равен 3,09375. Ещё два действия: принять предложение коалиции
по точной рекомендованной цене или пропустить торговлю. Всего 35 вариантов.
`price_levels` настраивается; оптимальность числа 33 отдельно не проверялась.

По умолчанию цены ниже себестоимости запрещены, включая коалиционные предложения.
`allow_loss_leading: true` разрешает их при неотрицательном резерве; это может быть полезно
при коалиционном субсидировании. Обязательные ограничения среды сохраняются.
Недопустимые действия исключаются и при выборе, и при вычислении следующего максимума Q.
Если допустимой цены нет, агент пропускает торговлю. Связями не управляет (`link_action=None`).

**Состояние.** Числовые признаки разбиты на категории. При настройках по умолчанию:

| Признаки | Категории |
|---|---|
| Средняя цена / собственная себестоимость | 6 / 4 равных диапазона цены |
| Соседи, ограничение резерва, предложение | Три флага наличия |
| Резерв | <0, от 0 до 500, >=500 |
| Маржа предложения / относительная доля выплаты | Границы 0, 5, 15, 30 / 0,8 и 1,2 для `weight × members` |
| Изменение средней цены | Падение / стабильность / рост, порог 8,25 |
| Средняя из последних 5 наград | <0, от 0 до 100, >100 |

Всего 10 признаков. Отсутствие цены или предложения имеет отдельный код.
`history` использует все признаки; `context` обнуляет только два исторических;
`basic` оставляет среднюю цену и три флага. **Личный вклад:** короткая память,
позволяющая различать похожие текущие ситуации с разной предысторией.

**Обучение.** `Q(s, a)` оценивает суммарную дисконтированную награду после действия:

```text
Q(s,a) += alpha × (reward / 100 + gamma × max Q(s_next, a_next) − Q(s,a))
```

На терминальном переходе будущая ценность равна нулю. Награда учитывает коалиционные
выплаты и штрафы. По умолчанию `alpha=0.15`, `gamma=0.95`,
`epsilon=max(0.05, 0.9995**updates)`: сначала случайные пробы, затем преимущественно выбор по Q.
В eval epsilon равен нулю; неизвестное состояние использует резервную стратегию без продажи ниже себестоимости.
`reset` очищает память эпизода, сохраняя Q и число обновлений. В eval память меняется,
Q и метаданные заморожены. Равные оценки разрешаются генератором с seed.

## Проверка памяти и результаты

```bash
python -m tverdokhleb_agent.experiment benchmark
```

Команда обучает `context/history` с начальными seed 42, 1042, 2042 и оценивает каждый
на 32 условиях × 3 новых seed. Отличаются только исторические признаки.
Результаты и модели: `runs/tverdokhleb_agent/benchmark/`; `comparison.json/.md` содержат
общие метрики, сценарии и парные различия. Параметры: `--variants`, `--train-seeds`, `--eval-seeds`.
Блоки обучающих seed не должны пересекаться. Известная строка Q не означает изученность всех действий.

Результаты 05.11.2026, средняя суммарная награда за эпизод:

| Сценарий | context | history | Без обучения | BestResponse |
|---|---:|---:|---:|---:|
| Конкуренция | 9126,49 | 10244,59 | 16294,57 | 18911,82 |
| Кооперация | 83813,62 | 98294,47 | 27505,91 | 119536,42 |
| Санкции | 83319,17 | 98291,28 | 27505,91 | 119536,42 |
| Смешанный | 6148,13 | 10357,55 | 22095,37 | 28568,16 |
| Все условия | 45601,85 | 54296,97 | 23350,44 | 71638,20 |

Все шесть моделей получили 29941–30000 обновлений и epsilon 0,05; выживание при оценке — 100%.
Парные различия history−context: +796,14; −673,58; +25962,79. Устойчивое преимущество памяти
не доказано, BestResponse сильнее; выигрыш относительно необученного агента зависит от сценария.

Первый history-чекпойнт на исходном `random/evolving` YAML дал 10957,49 против 22897,55
без обучения и 29444,61 у BestResponse, при выживании 100% и 98,33% известных состояний.
Эту проверку повторяет команда `evaluate --checkpoint .../repeat_0/history.json` выше.
Модель выбрана по номеру повтора, без отбора по проверочной награде. Артефакты `runs/` не входят в Git.

## Тесты

```bash
python -m pytest -q
```

Эксперименты относятся к отдельному агенту и не заменяют совместные циклы адаптации
с обучаемым арбитром и общую защиту команды.
