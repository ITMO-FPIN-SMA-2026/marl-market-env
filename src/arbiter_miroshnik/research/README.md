# Командное обучение PPO + GRU

Для обычного запуска используйте [конфиг пакета](../README.md#подключение).
Этот launcher предназначен для экспериментов с четырьмя обучающимися продавцами,
контрольной популяцией и тремя независимыми моделями арбитра.

## Подготовка

`sources.py` извлекает закреплённые реализации агентов и коалиционной политики
из локальных `origin/agent-*` и `origin/coalition` Git refs. Их копии и SHA-256
сохраняются в каталоге эксперимента; среда импортируется из текущего репозитория.
Эти refs должны быть доступны до запуска подготовки. Launcher не загружает их
из сети и не переключает ветку.

`prepare` принимает исходные обученные checkpoint схемы 3:

```bash
python -m arbiter_miroshnik prepare --out runs/ppo_team \
  --source-checkpoint /path/to/model_0.pt \
  --source-checkpoint /path/to/model_1.pt \
  --source-checkpoint /path/to/model_2.pt
```

Actor и critic сохраняются численно; оптимизаторы и старые траектории сбрасываются.
Публичная калибровка выполняется на независимых продавцах без коалиций.
Встроенный `checkpoints/initial_model_0.pt` уже имеет схему 4 и используется
готовым YAML напрямую; он не является входом этой конверсии.

## Обучение и оценивание

Для подготовленного каталога:

```bash
python -m arbiter_miroshnik train --out runs/ppo_team --games 128 --device cpu
python -m arbiter_miroshnik evaluate --out runs/ppo_team --episodes 20 --device cpu
```

`--games` задаёт целевое общее число игр каждой модели. Повторный запуск продолжает
actor, critic, Adam, незавершённые пакеты PPO и состояния обеих популяций продавцов.
Одновременно допускается один обучающий процесс на каталог.

Штатный `run_episode` выполняет шаги среды; `summarize_episode` считает основные
метрики с точностью шесть знаков. Дополнительно проверяется отсутствие ошибок
командного кода и неизменность обученных параметров при оценивании.
Логи при обучении записываются в gzip; старые этапы и отчёты не перезаписываются.

Оценивание сравнивает адаптированные регулируемую и контрольную популяции,
отключает арбитра на тех же регулируемых продавцах и проверяет ложные санкции
на независимых продавцах без коалиций. `--eval-seed` задаёт новый блок миров.
Награда берётся из `social_market_env.core.scoring`; метки вреда и `SW*`
используются средой для оценивания, а не как признаки сетей.

## Состояния

- `initial_model_N.pt` — начальные сети и публичная калибровка.
- `train/model_N/arbiter/weights/` — PPO, Adam и траектории после каждой игры.
- `train/model_N/game_*/` — обе популяции продавцов, метрики и логи.
- `train/model_N/progress.json` — общий прогресс арбитра и продавцов.
- `train/model_N/arbiter/index.json` — перечень checkpoint и SHA-256.

Результаты и ограничения опубликованных серий находятся в
[docs/experiments.md](../docs/experiments.md).
