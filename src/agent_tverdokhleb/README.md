# Рыночный агент Твердохлеб

**Автор: Роман Твердохлеб.**

**Модуль:** `src/agent_tverdokhleb/`. **Роль:** Market Agent, контракт `MarketAgentAPI` версии `2.0.0`.

## Результаты работы для слайда

Реализован `TverdokhlebAgent` на табличном Q-learning. Он выбирает цену из 33 уровней,
принимает предложение коалиции или пропускает торговлю. Недопустимые действия исключаются.
**Личный вклад:** короткая память о динамике средней цены и пяти последних наградах.
Добавлены сохранение модели, обучение на меняющихся рынках и парное сравнение стратегий.

Проверка от 05.11.2026: пять продавцов, logit, горизонт 100 шагов. Для `context` без памяти
и `history` с памятью выполнены по три обучения по 300 эпизодов. Оценка каждого обучения:
32 условия × 3 новых seed при одинаковых издержках и seed сброса. Остальные признаки,
действия и гиперпараметры вариантов совпадают. Метрика: суммарная награда за эпизод.

| Политика | Средняя награда | Выживание |
|---|---:|---:|
| Q-learning без памяти (`context`) | 45 601,85 | 100% |
| Q-learning с памятью (`history`) | 54 296,97 | 100% |
| Без обучения, резервная стратегия | 23 350,44 | 100% |
| `BestResponseAgent` | 71 638,20 | 100% |

**Вывод:** средний результат с памятью выше, но её устойчивое преимущество не доказано.
Разница `history − context` по обучениям: +796,14; −673,58; +25 962,79. BestResponse сильнее.
Выигрыш относительно необученного агента зависит от сценария:

| Сценарий | history | Без обучения | BestResponse |
|---|---:|---:|---:|
| Конкуренция | 10 244,59 | 16 294,57 | 18 911,82 |
| Кооперация | 98 294,47 | 27 505,91 | 119 536,42 |
| Санкции | 98 291,28 | 27 505,91 | 119 536,42 |
| Смешанный | 10 357,55 | 22 095,37 | 28 568,16 |

На исходном `random/evolving` YAML первый history-чекпойнт получил 10 957,49 против
22 897,55 без обучения и 29 444,61 у BestResponse. Модель выбрана по номеру повтора,
без отбора по проверочной награде. Результаты относятся к штатным соперникам;
совместная адаптация с агентами группы и MARL-арбитром здесь не заявляется.

## Подключение

Из корня репозитория в активированном Python-окружении (>=3.11):

```bash
python -m pip install -e '.[dev]'
python -m social_market_env.run src/agent_tverdokhleb/experiments/agent_tverdokhleb.yaml
```

Готовый [конфиг](experiments/agent_tverdokhleb.yaml) ставит нашего агента на место 0
среди пяти продавцов. **Без чекпойнта это резервная стратегия, а не обученная модель.**
В собственном YAML достаточно указать:

```yaml
agents:
  overrides:
    0:
      impl: "agent_tverdokhleb:TverdokhlebAgent"
      kwargs: {model_path: "runs/tverdokhleb_agent/policy.json"}
```

`model_path` указывайте после обучения; без него агент начинает с пустой Q-таблицы.
Параметры рынка передаёт штатный загрузчик. При загрузке модели нельзя одновременно
задавать `config`: настройки уже записаны в JSON. Относительные пути считаются от рабочей папки.

## Обучение и воспроизведение

```bash
python -m agent_tverdokhleb.experiment train
python -m social_market_env.run runs/tverdokhleb_agent/policy.eval.yaml
python -m agent_tverdokhleb.experiment evaluate
python -m agent_tverdokhleb.experiment benchmark
```

- `train`: новая модель, 300 эпизодов × 100 шагов, seed 42–341, минимум 10000 фактических
  переходов. Сохраняет `policy.json`, `policy.training.json` и `policy.eval.yaml`.
- `evaluate`: готовая модель против резервной стратегии и BestResponse на исходном YAML;
  `--suite matrix` включает все 32 условия. Выход: `evaluation.json/.md`.
- `benchmark`: отдельные обучения context/history с начальными seed 42, 1042, 2042;
  оценка на seed 100000–100002, общие результаты и разбивка по сценариям в `comparison.json/.md`.

Обучение и benchmark используют четыре состава рынка (`competition/cooperation/sanctions/mixed`),
четыре топологии (`complete/star/path/inner_coalitions`) и два режима сети (`static/evolving`).
Они заменяют сеть из `--config`; только `mixed` сохраняет его соперников, коалиции и арбитра.
`evaluate` по умолчанию сохраняет исходную постановку. Проверочные seed не пересекаются с обучающими.

Все артефакты остаются в игнорируемой папке `runs/tverdokhleb_agent/`. Параметры доступны
через `<команда> --help`. Короткая проверка запуска, не полноценное обучение:

```bash
python -m agent_tverdokhleb.experiment train --episodes 4 --horizon 5 --min-updates 10 --output runs/tverdokhleb_agent/smoke/policy.json
```

## Устройство агента

- **Состояние:** 10 категориальных признаков средней цены, себестоимости, резерва,
  соседства, ограничений, предложения коалиции и истории. `context` обнуляет только
  два исторических признака; `history` использует их. Дополнительный режим `basic` оставляет четыре признака.
- **Действия:** 33 равномерные цены от 1 до 100 (шаг 3,09375), точное принятие предложения
  или пропуск торговли. Число уровней настраивается; его оптимальность не проверялась.
- **Память:** падение/стабильность/рост средней цены (порог 8,25 при настройках по умолчанию)
  и категория средней из пяти последних наград: <0, от 0 до 100, >100.
- **Обучение:** `Q += α × (reward/100 + γ × max Qnext − Q)`, `α=0.15`, `γ=0.95`,
  `ε=max(0.05, 0.9995**updates)`. На терминальном переходе будущая ценность равна нулю.
- **Ограничения:** по умолчанию нет цен ниже себестоимости. Маски действуют и при выборе,
  и в следующем максимуме Q. `allow_loss_leading: true` разрешает убыточные цены при отсутствии
  ограничений среды. Связями агент не управляет (`link_action=None`).
- **Оценка:** Q и метаданные заморожены, ε=0; неизвестное состояние использует допустимую
  цену, ближайшую к `cost + 5`. `reset` очищает память эпизода, сохраняя обучение.

Формат модели v3 сохранён. Старые JSON v3 совместимы; в старых YAML замените импорт
`tverdokhleb_agent:TverdokhlebAgent` на `agent_tverdokhleb:TverdokhlebAgent`.
Модели MVP/v2 требуют переобучения. `checkpoint_path` позволяет сохранять модель после
терминального перехода в native-обучении; поддерживаются `{agent_id}` и `{seed}`.
